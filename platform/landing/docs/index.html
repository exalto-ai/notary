How Exalto fits.

Run your existing model client through a local proxy, keep encrypted evidence on your machine, and seal only the interactions you choose into independently verifiable OpenTelemetry trace packages.

The workflow

  1. 01
    Capture

    Point an SDK or agent at the local proxy. Requests and streamed responses continue normally while each completed provider call becomes an encrypted local capture, witnessed as ciphertext by the notary you chose at setup.

  2. 02
    Choose

    Captures wait on your disk. Nothing is shared automatically, and interactive model use does not wait for the expensive proof step.

  3. 03
    Seal

    Turn a selected capture into authenticated TLS evidence and a deterministic OpenTelemetry trace: the portable .llmtrace receipt. This can happen long after the original model call.

  4. 04
    Verify or share

    Check the package locally, keep it private, or deliberately share its disclosed conversation and portable proof through a stable link.

One trace, two evidence states

CAPTURED

Private local evidence

The trace retains a sensitive encrypted capture that can be sealed later. It is not yet evidence another person can verify.

SEALED

Portable trace package

TLSNotary evidence, disclosed authenticated HTTP, the canonical OpenTelemetry trace, and a manifest binding the files together.

Sharing is a separate action

A sealed trace can remain local or be shared deliberately. Sharing hosts the exact admitted .llmtrace package and its disclosed conversation; it does not create another evidence state.

What is automatic

  • The first start creates or opens the local encrypted-capture vault. On a desktop OS, its random key is stored in the system credential service.
  • The service discovers the production notary endpoint and public key from the public Registry, then pins that trust information locally.
  • Sealing and verification use the pinned notary identity. Normal hosted use does not require copying a public key into an API request.
  • Provider credentials remain in your existing SDK or agent environment; nothing asks for or stores them.

The claim

A trusted notary attests that disclosed bytes came from an authenticated TLS interaction with the named provider, and the OpenTelemetry representation is deterministically bound to those bytes. A trace proves presence, never absence.

Exalto Seal is not a notary public. Sealing is not a notarial act. A receipt is cryptographic evidence, not a legal instrument. The ENP specification uses "notary" as a technical role term, in the way public-key infrastructure uses "certificate authority."
